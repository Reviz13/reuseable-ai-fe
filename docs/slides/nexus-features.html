The idea

One widget, many apps, each with its own brain

Each app (POS, Core Banking, ERP/HRIS) is a tenant with isolated knowledge, tools, persona and avatar. POS is the pilot.

📚

Answers from knowledge

SOPs, manuals and FAQs managed by admins. Every answer cites its source documents.

📈

Reports profit

Today, yesterday, this/last week, this/last month or a custom range. Owners only.

😺

Shows how it feels

A character avatar whose expression follows the conversation: idle, thinking, talking, happy, sad.

🔒

Read-only by design. NEXUS never writes to an application database, and profit is calculated by the POS backend, never by the model.

Profit for the owner

“Profit this week?” gets the POS’s own numbers

  • One read-only tool, pos.get_profit, calls the POS report; the model never calculates.
  • Number guardrail: every rupiah amount in the answer must equal a tool value, or the whole answer is replaced by a safe template.
  • Honest caveats: items sold without COGS are always called out.
  • Every call audited, including refused and failed ones.

Who, when and how much is decided in code

PeriodRange

customup to 92 days, never in the future

Owner only

Role, outlet and time zone come from the verified token. The model cannot pass them, so prompt text cannot change them.

Resilient

5 s timeout with one retry. Bad ranges return INVALID_PERIOD and NEXUS asks to rephrase.

Time zones

WIB, WITA and WIT outlets resolve their own “today”.

NEXUS · Feature overview6
Knowledge answers

Step-by-step SOPs, with their sources

  • Retrieval-augmented: the question is matched against active document chunks for this app only.
  • Citations show exactly which SOP or FAQ the answer came from.
  • “I don’t know” is allowed: below the score threshold NEXUS says so and logs a knowledge gap.
  • Injection-safe: document text is treated as data, never as instructions.

Security & guardrails

Safe by construction, not by prompt

Signed identity

RS256 JWT from the host, 10-minute TTL, verified per app via JWKS.

Tenant isolation

Retrieval always filters by app and active version; tools are registered per app.

Locked database

RLS on every table with no policies; only ai-service holds the service key.

Append-only audit

UPDATE and DELETE revoked and blocked by a trigger, even for the service role.

Abuse limits

CORS limited to allowed origins; 20 messages per minute per user.

No secrets in the browser

The widget holds no keys; Studio holds only the anon key.

NEXUS · Feature overview14
Models & data

Swap the model per app; keep the data in one place

LLM gateway

  • Claude adapter for cloud use.
  • OpenAI-compatible adapter for self-hosted models (LM Studio, Ollama, vLLM). The demo runs qwen2.5-7b-instruct locally.
  • Fallback adapter on failure, after one retry.
  • Fake adapter for deterministic tests.

Supabase

  • Postgres + pgvector with an HNSW index for chunks.
  • Storage for knowledge files and avatar frames.
  • Conversations, feedback, gaps, audit tables.
  • 90-day retention for conversations.
